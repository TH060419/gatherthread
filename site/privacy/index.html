隐私说明

共序为多人协作服务，Beta 测试采用公开邮箱注册。以下说明适用于官方服务；自托管实例的运营者应公布自己的存储位置、备份和日志保留安排。独立测试服可要求测试人员代码，它不代表正式服的注册要求。

消息删除、账号注销与以下保留期限随新版服务器部署后生效。仅更新仓库源码不会启用清理任务；上线前维护者须核验服务器及异地备份、快照和日志的实际保留设置。

我们处理什么

为提供协作服务，我们保存账号显示名、设备名称和凭据摘要、项目成员关系、共享会话消息与 Agent 输出、可选上传的云端 Git 代码检查点，以及必要的安全与运行日志。设备访问 Token 不以明文保存在服务端。你本地 Codex / DeepSeek Harness / Claude Code 的文件、原生会话和模型凭据不会因为登录而自动上传；连接器或插件只按你启用的功能上传选定内容。

Claude Code 原生会话上传默认关闭，需逐会话授权。你同意自动或手动上传后，连接器只读取已绑定会话中该回合附近的有限本地记录，用于核对提问、最终回答与实际模型；不会上传原始记录或隐藏推理。未上传内容及文件位置校验信息保留在电脑的私有同步状态中，其他本地会话不会被扫描。文件同步另需授权，不能由连接或聊天自动开启。

云端体验 Agent 与模型服务

在「设置 → 个人 API」主动添加的模型密钥，仅供你的账号使用，服务器以独立密钥加密保存，不会回显或保存至浏览器存储。运行时仅服务器代理向所选官方服务商使用此密钥，执行容器不接收真实密钥。服务商对你的账号计费；你的任务及选择的会话历史、文件按与云端体验相同的规则发送。暂停、修改或删除配置会中止使用旧配置的任务；已发出的服务商请求无法撤回或退费。删除配置或注销账号会移除在线密钥记录，常规备份仍适用下述最多 14 天保留期限。

从共序请求 Agent 时，原生界面已提供的回答、思考摘要、工具过程与计划可实时保存到共享会话，供该会话成员查看，并可折叠显示。未提供的隐藏推理不会被提取；无关本地会话不会因该功能自动上传。系统会对选定字段做脱敏，但不能保证识别所有秘密，请勿在任务或文件中放入不愿共享的信息。

主动请求云端体验 Agent 时，你的任务、按项目历史设置整理的共享会话内容，以及已开启选项允许使用的 GT Cloud 项目代码，会发送给所选模型服务商处理。“使用 GT Cloud 代码”默认开启，浏览器按账号和项目记住开启或关闭的选择，发送后不会自动清除；提交前请检查此选项。GT Cloud 文件共享未启用或无写权限时不会发送项目代码。关闭此选项时，任务在空的临时目录运行；临时目录在任务结束后清理，最终回答仍保存在共享会话中，按该会话权限供成员查看。不要提交不愿交给模型服务商处理的秘密。模型服务商的处理地点、保留及删除规则由其政策和实际服务配置决定，不受共序的 14 天备份清理期限控制；运营者须在开放服务前核验并披露实际服务商及变化。使用方式与限制见云端体验指南。

为执行使用额度，服务端保留最小任务标识、账号标识、使用日与配额组记录，不包含会话正文或源码。删除会话、任务或账号不会退还当日已使用的额度；过期使用日记录在服务启动或接受新任务时清理。

邮箱注册、密码登录与找回密码

邮箱用于发送短期验证码与标识登录账号，密码用于后续登录；注册与找回密码的开放状态以登录页面为准。服务器不保存邮箱明文、验证码或密码明文，仅保留带私密 pepper 的邮箱摘要、短期验证码摘要与随机盐密码摘要；摘要仍是化名个人数据。项目成员不能读取邮箱或密码摘要。用户使用邮箱和密码登录，同一账号可在多台设备同时使用；Agent 使用独立设备授权。

为自动填好 Codex 或 Claude Code 启动器的邮箱，浏览器可在当前标签页保存与账号绑定的邮箱提示，有效期最多 1 天；勾选“记住此设备”时可在该浏览器本地保存，有效期最多 30 天。到期后不再用于预填，并在下次读取时清除；退出登录也会清除。邮箱提示不是登录凭据，不包含密码或令牌。打开启动器的链接包含邮箱及一次性请求编号，操作系统可能记录此类应用打开信息；仍需在启动器输入密码才能授权。启动器不保存密码，连接后可在设置中单独撤销该设备。

勾选确认后才加载 Cloudflare Turnstile 安全检查，Cloudflare 会按其隐私补充说明处理浏览器及网络信息。验证邮件通过运营者配置的邮件服务发送；当前适配 Resend，它会处理收件地址、邮件验证码及发送状态，按其隐私政策与服务保留设置处理。开通前运营者应核验实际服务商、境外处理与保留安排，并向用户公布变化。我们不把验证码、密码或令牌写入 URL、普通日志或浏览器本地存储。

待验证记录到期后在运行中一分钟内清理（验证码有效期 10 分钟）；限流摘要随其预算窗口到期，最长 31 天。邮箱标识及密码摘要保留至注销，账号注销时在线删除，另保留 30 天邮箱摘要以防立即重复注册绕过防刷预算。浏览器保留 30 天 HttpOnly 标识，用于把密码登录绑定至各自设备，该标识本身不能登录。备份按下述 14 天政策处理，邮件服务商与用户收件箱中的邮件需按其各自政策处理。找回密码单独启用，使用相同的邮件及安全检查服务发送验证码和密码重设通知。重设会撤销所有登录设备及 Agent 授权。暂不支持变更邮箱。

项目成员可见范围

项目成员可以读取该项目的共享会话历史和已上传的云端代码；Solo 限制其他人的写入，不是私人存储。请勿上传不愿与项目成员分享的秘密信息。共享 Multi 消息及代码中由用户自行输入的姓名或其他识别信息，不会因为账号注销而被自动改写。

删除自己发出的消息

有发言权限时，可用消息旁的垃圾桶删除自己发出的聊天消息、Agent 请求和归属自己的 Agent 回复；创建者也不能删除其他成员的消息。正文替换为删除占位，消息标识、顺序、类型、作者、时间与引用关系仍保留。删除请求会同时使其回复和工作过程失效；相关摘要及可能使用过这段历史的后续生成内容也会失效。

后续由 GatherThread 整理给 Agent 的历史不再包含被删除的内容和这些失效结果；切换原文、查看旧版本或重新下载历史都不能恢复它们。使用旧历史的任务不再接受新输出，请重新请求；旧版连接器须先更新并重新连接。受影响的旧共序本地会话仍保留为仅本地副本，不会再上传。

删除不回滚已经执行的文件改动，不删除其他成员的独立消息或手工重发的副本，也不删除电脑文件或原有本地会话。已经发送给模型服务商的内容或保存的离线副本，无法由共序立即撤回；其保留规则独立。

可选的本地直连 GitHub 文件同步

若选择电脑直连 GitHub 文件同步，代码由已授权的本地连接器直接上传至你指定的 GitHub 仓库，不经过共序服务器。在这一同步方式中，共序仅保存仓库名称、分支配置和操作状态，不接收 GitHub 登录凭据。GitHub 仓库的公开或私有设置、协作者权限与保留策略独立于共序；公开仓库内容可能被任何人读取。个人分支名中的项目与账号摘要是稳定的化名标识，并非匿名保证。暂停同步、退出共序项目或注销共序账号不会撤销 GitHub 权限、删除 GitHub 分支或历史；请在 GitHub 中另行处理。下述共序 14 天备份及 Git 对象保留期限不适用于 GitHub、其 Actions 产物或他人克隆的副本。

云端 GitHub 仓库任务是另一种需单独启用和授权的功能，不属于上述电脑直连同步。若使用它，共序服务器加密保存授权凭据和私有任务源码，读取你授权的仓库，并将任务及所选内容交给所选模型服务商。任务有效期七天，到期后不再提供读取；已过期且不再运行的私有任务源码，在服务启动或相关请求触发清理时删除，删除后的备份另按下述保留政策处理。任务最终回答进入共享会话。删除保存的任务不会删除 GitHub 分支或 PR；断开云端 GitHub 会移除共序保存的连接凭据，GitHub 端授权应另行撤销。详见云端 GitHub 任务说明。

注销账号

可在工作页面“设置 → 账号与隐私”自行注销。须先把拥有的项目移交给现有参与者，或删除这些项目，并处理个人云端代码分支。注销前页面会显示即将删除的 Solo 云端会话数量。确认后，Solo 云端会话被删除，设备凭据、登录状态和成员关联被撤销；Multi 的共享记录继续保留，但服务端作者账号关联改为“已注销成员”。本地 Agent 会话、工作目录和设备文件不会由共序远程删除。

删除后的保留期限

消息删除事务完成后，在线服务不再提供已删除正文或失效派生内容；注销事务完成后不再提供被删除的 Solo 会话和账号数据。底层存储和离线副本不会瞬间物理清除，按保留与清理政策处理。包含已删除内容的常规备份，以及删除后不再可达的云端 Git 对象，保留最多 14 天；含用户标识的常规运行与安全日志保留最多 30 天。期限从对应数据删除或日志产生之日起计算。备份只用于灾难恢复，不作为普通会话访问；恢复旧备份时必须重新应用期间的注销与删除记录，不能使已删除账号或正文重新上线。

共享 Multi 内容、仍可从项目代码主线或其他成员分支到达的 Git 对象，不属于“删除后不再可达”的数据，会随项目继续保留。Git 提交元数据可能保留原作者显示名；账号注销不重写共享 Git 历史。用户自己导出的副本、其他成员的本地副本、第三方 Agent / 模型服务中的数据不受共序服务器清理控制。如依法需要保全证据，可能需延长个别受限副本的保留，并应单独记录和告知适用范围。

Privacy notice

GatherThread is a collaboration service whose Beta uses public email registration. This notice applies to the official service. Self-hosted operators should publish their own storage, backup and log-retention practices. A separate test environment may require a tester admission code; this is not a production registration requirement.

Message deletion, account deletion and the retention limits below take effect when the updated server is deployed. Updating source code alone does not enable cleanup jobs; before rollout, the operator must verify the live server and off-host backup, snapshot and log retention settings.

What we process

To provide collaboration, we store account display names, device names and credential digests, project memberships, shared conversation and Agent output, optional cloud Git checkpoints, and necessary security and operational logs. Device access tokens are not stored in plaintext on the server. Signing in does not automatically upload local Codex / DeepSeek Harness / Claude Code files, native conversations or model credentials; connectors and plugins upload selected content only for features you enable.

Native Claude Code conversation upload starts off and needs per-conversation approval. After you approve automatic or manual upload, the connector reads only a bounded region near that turn in the bound conversation's local records to verify the prompt, final answer and actual model. Raw records and hidden reasoning are not uploaded. Pending turns and file-verification metadata remain in private synchronization state on your computer; other local conversations are not scanned. File synchronization needs separate consent and cannot be enabled by connecting or chatting alone.

Cloud trial Agent and model providers

Model keys you explicitly add under Settings → Personal API belong only to your account. The server encrypts them under a separate key; they are never returned or saved in browser storage. Only the server proxy uses the real key with the selected official provider; execution containers do not receive it. Your provider bills your account, and tasks, selected history and files follow the cloud trial's disclosure rules. Pausing, editing or deleting a configuration stops work using the old settings; already dispatched provider requests cannot be recalled or refunded. Deleting the configuration or account removes its live key record; regular backups still follow the maximum 14-day retention below.

When you request an Agent through GatherThread, its native-exposed answers, thinking summaries, tool activity and plans may be saved live in the shared conversation for its members, with collapsible display. Unavailable hidden reasoning is not extracted, and unrelated local conversations are not automatically uploaded by this feature. Selected fields are redacted, but not every secret can be recognized; do not put information you do not want to share in tasks or files.

When you explicitly request the cloud trial Agent, your task, shared conversation context prepared under the project's history settings and GT Cloud project code allowed by the enabled selection are sent to the selected model provider. “Use GT Cloud code” starts on; the browser remembers the on/off choice for each account and project instead of clearing it after sending. Review it before submitting. With GT Cloud file sharing disabled or without write access, project code is not sent. With the option off, the task uses an empty temporary directory. That directory is cleaned up after the task; the final answer remains in the shared conversation, visible under its membership rules. Do not submit secrets you do not want the model provider to process. Provider processing locations, retention and deletion follow its policy and actual service configuration, not GatherThread's 14-day backup cleanup limit. Operators must verify and disclose the actual providers and changes before opening the service. See the cloud trial guide for use and limits.

To enforce usage allowances, the server retains minimal task and account identifiers, usage day and quota-group records, without conversation bodies or source. Deleting a conversation, task or account does not refund that day's usage. Records for expired usage days are pruned at server startup or when a new task is accepted.

Email registration, password sign-in and recovery

Email identifies a sign-in account and receives short-lived codes; passwords enable later sign-in. The sign-in page shows whether registration and recovery are available. The server retains keyed email digests, short-lived code digests and salted password hashes, not plaintext email, codes or passwords. Digests are pseudonymous personal data. Project members cannot read these credential records. Users sign in with email and password and may use the same account on multiple devices simultaneously; Agents use independent device authorization.

To prefill the Codex or Claude Code Launcher email, the browser may keep an account-bound email hint valid for up to one day in the current tab, or up to 30 days locally when you choose Remember this device. Expired hints are no longer used and are cleared on their next read; signing out also clears them. The hint cannot authenticate and contains no password or token. The app-opening link includes the email and a one-use request identifier; the operating system may retain app-opening metadata. You must still enter your password in the Launcher to authorize it. The Launcher does not save passwords, and its device can be revoked separately in Settings.

Cloudflare Turnstile loads only after acknowledgment and processes browser/network information under its Privacy Addendum. The configured mail provider handles recipient addresses, code content and delivery status. The current adapter uses Resend under its privacy policy and retention settings. Before opening, operators must verify providers, cross-border processing and actual retention, and disclose any change. Codes, passwords and tokens do not enter URLs, ordinary logs or browser local storage.

Pending records are removed within one minute of expiry while the host runs (codes last ten minutes). Budget digests expire with their windows, at most 31 days. Active email identifiers/password hashes last until account deletion; deletion removes them from the live service while retaining a mailbox digest for 30 days to prevent immediate signup-budget evasion. A 30-day HttpOnly browser marker binds password sign-ins to independent devices and cannot authenticate by itself. Backups follow the 14-day policy below; provider and recipient mailbox copies follow their own policies. Password recovery is enabled separately and uses the same mail and security-check providers for codes and password-change notices. Resetting revokes all signed-in devices and Agent authorizations. Email changes are not supported.

What project members can see

Project members can read that project's shared conversation history and uploaded cloud code. Solo restricts others' writing; it is not private storage. Do not upload secrets you do not want project members to see. A user's name or other identifying information written into shared Multi content or code is not automatically rewritten when that account is deleted.

Delete your own messages

With write access, use the trash icon beside your own chat messages, Agent requests and Agent replies. The owner cannot delete another member's messages. The body becomes a deletion placeholder; message identity, type, order, author and time, and reply references remain. Deleting a request also invalidates its replies and work. Related summaries and later generated content that may have used this history are also invalidated.

All future GatherThread-prepared Agent history will exclude deleted content and these invalidated results. Switching to originals, viewing old versions or downloading history again cannot restore them. Work using older history cannot publish new output; start a new request. Older connectors must be updated and reconnected first. For the affected conversation, older GatherThread-created local tasks remain local-only and are not uploaded again.

Deletion does not roll back already executed file changes or remove other members' independent messages or manual reposts. It does not delete computer files or existing local conversations. GatherThread cannot immediately recall content already sent to a model provider or saved in independent offline copies; their retention rules are separate.

Optional direct computer-to-GitHub file synchronization

If you choose direct computer-to-GitHub synchronization, an authorized local connector uploads code directly to your selected GitHub repository, not through GatherThread servers. In this sync mode, GatherThread stores repository and branch configuration and operation status, not GitHub credentials. GitHub visibility, collaborator access and retention are independent of GatherThread; a public repository may be read by anyone. Project and account digests in personal branch names are stable pseudonymous identifiers, not a guarantee of anonymity. Pausing synchronization, leaving a GatherThread project or deleting a GatherThread account does not revoke GitHub access or delete GitHub branches or history. Manage those separately on GitHub. The 14-day GatherThread backup and Git-object limits below do not apply to GitHub, its Actions artifacts or other people's clones.

Cloud GitHub repository tasks require separate activation and authorization; they are not the direct computer sync above. If you use them, GatherThread encrypts stored authorization credentials and private task source, reads your authorized repository and sends the task and selected content to the selected model provider. Tasks expire after seven days and can no longer be read. Expired private task source is deleted at server startup or when related requests trigger cleanup, once the task is no longer running; backups after deletion follow the retention policy below. The final answer enters the shared conversation. Deleting a saved task does not delete GitHub branches or PRs. Disconnecting cloud GitHub removes GatherThread's stored connection credentials; revoke GitHub-side authorization separately. See cloud GitHub tasks.

Delete your account

Use “Settings → Account & privacy” in the workspace. First transfer every project you own to an existing participant or delete it, and resolve personal cloud code branches. The page previews how many Solo cloud conversations will be deleted. After confirmation, Solo cloud conversations are deleted, device credentials, sessions and membership links are revoked, and shared Multi records remain with their server-side author account association changed to “Deleted member”. GatherThread does not remotely delete local Agent conversations, workspaces or files.

Retention after deletion

After the message-deletion transaction, the live service stops serving erased bodies and invalidated derived content; after account deletion, it stops serving deleted Solo conversations and account data. Physical erasure of underlying storage and offline copies is not instant and follows retention and cleanup policies. Routine backups containing deleted material, and cloud Git objects that become unreachable after deletion, are retained for no more than 14 days; routine operational and security logs containing user identifiers are retained for no more than 30 days. The clock starts when the relevant data is deleted or the log is created. Backups are used only for disaster recovery, not ordinary conversation access; restoring an older backup must reapply subsequent account and content deletions before serving users.

Shared Multi content and Git objects still reachable from a project's main line or another member's branch are not “unreachable after deletion” and remain with the project. Git commit metadata may retain the original author's display name; account deletion does not rewrite shared Git history. User exports, other members' local copies and data held by third-party Agents or model providers are outside the GatherThread server's deletion control. If evidence must be preserved by law, an individual restricted copy may need a longer retention period, with its scope separately recorded and disclosed.
