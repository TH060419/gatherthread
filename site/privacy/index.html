隐私说明

共序为邀请制 Alpha 协作服务。以下说明适用于官方服务；自托管实例的运营者应公布自己的存储位置、备份和日志保留安排。

账号注销与以下保留期限随新版服务器部署后生效。仅更新仓库源码不会启用清理任务；上线前维护者须核验服务器及异地备份、快照和日志的实际保留设置。

我们处理什么

为提供协作服务，我们保存账号显示名、设备名称和凭据摘要、项目成员关系、共享会话消息与 Agent 输出、可选上传的云端 Git 代码检查点，以及必要的安全与运行日志。设备访问 Token 不以明文保存在服务端。你本地 Codex / DeepSeek Harness 的文件、原生会话和模型凭据不会因为登录而自动上传；连接器或插件只按你启用的功能上传选定内容。

可选邮箱注册与密码登录（待上线功能）

官方 Alpha 目前未开放邮箱注册。运营者明确开启后，邮箱用于发送短期验证码与标识登录账号，密码用于后续登录。我们不保存邮箱明文、验证码或密码明文，仅保留带私密 pepper 的邮箱摘要、短期验证码摘要与随机盐密码摘要；摘要仍是化名个人数据。邮箱账号的项目权限与资格码激活账号一致，项目成员不能读取邮箱或密码摘要。已有账号不会自动绑定或合并。

勾选确认后才加载 Cloudflare Turnstile 安全检查，Cloudflare 会按其隐私补充说明处理浏览器及网络信息。验证邮件通过运营者配置的邮件服务发送；当前适配 Resend，它会处理收件地址、邮件验证码及发送状态，按其隐私政策与服务保留设置处理。开通前运营者应核验实际服务商、境外处理与保留安排，并向用户公布变化。我们不把验证码、密码或令牌写入 URL、普通日志或浏览器本地存储。

待验证记录到期后在运行中一分钟内清理（验证码有效期 10 分钟）；限流摘要随其预算窗口到期，最长 31 天。邮箱标识及密码摘要保留至注销，账号注销时在线删除，另保留 30 天邮箱摘要以防立即重复注册绕过防刷预算。浏览器保留 30 天 HttpOnly 标识，用于把密码登录绑定至各自设备，该标识本身不能登录。备份按下述 14 天政策处理，邮件服务商与用户收件箱中的邮件需按其各自政策处理。目前不提供找回密码、变更邮箱或把旧资格账号转换成邮箱账号。

项目成员可见范围

项目成员可以读取该项目的共享会话历史和已上传的云端代码；Solo 限制其他人的写入，不是私人存储。请勿上传不愿与项目成员分享的秘密信息。共享 Multi 消息及代码中由用户自行输入的姓名或其他识别信息，不会因为账号注销而被自动改写。

可选的 GitHub 文件同步

若选择 GitHub 文件同步，代码由已授权的本地连接器直接上传至你指定的 GitHub 仓库，不经过共序服务器。共序仅保存仓库名称、分支配置和操作状态，不接收 GitHub 登录凭据。GitHub 仓库的公开或私有设置、协作者权限与保留策略独立于共序；公开仓库内容可能被任何人读取。个人分支名中的项目与账号摘要是稳定的化名标识，并非匿名保证。暂停同步、退出共序项目或注销共序账号不会撤销 GitHub 权限、删除 GitHub 分支或历史；请在 GitHub 中另行处理。下述共序 14 天备份及 Git 对象保留期限不适用于 GitHub、其 Actions 产物或他人克隆的副本。

注销账号

可在工作页面“设置 → 账号与隐私”自行注销。须先把拥有的项目移交给现有参与者，或删除这些项目，并处理个人云端代码分支。注销前页面会显示即将删除的 Solo 云端会话数量。确认后，Solo 云端会话被删除，设备凭据、登录状态和成员关联被撤销；Multi 的共享记录继续保留，但服务端作者账号关联改为“已注销成员”。本地 Agent 会话、工作目录和设备文件不会由共序远程删除。

删除后的保留期限

在线服务在注销事务完成后立即停止提供被删除的 Solo 会话和账号数据。包含已删除内容的常规备份，以及删除后不再可达的云端 Git 对象，保留最多 14 天；含用户标识的常规运行与安全日志保留最多 30 天。期限从对应数据删除或日志产生之日起计算。备份只用于灾难恢复，不作为普通会话访问；恢复旧备份时必须重新应用期间的注销与删除记录，不能使已删除账号重新上线。

共享 Multi 内容、仍可从项目代码主线或其他成员分支到达的 Git 对象，不属于“删除后不再可达”的数据，会随项目继续保留。Git 提交元数据可能保留原作者显示名；账号注销不重写共享 Git 历史。用户自己导出的副本、其他成员的本地副本、第三方 Agent / 模型服务中的数据不受共序服务器清理控制。如依法需要保全证据，可能需延长个别受限副本的保留，并应单独记录和告知适用范围。

联系

隐私或注销问题请发送至 coolhezi@sjtu.edu.cn。不要在公开 Issue 中粘贴 Token、邀请密钥、私人聊天或代码。

Privacy notice

GatherThread is an invitation-only Alpha collaboration service. This notice applies to the official service. Self-hosted operators should publish their own storage, backup and log-retention practices.

Account deletion and the retention limits below take effect when the updated server is deployed. Updating source code alone does not enable cleanup jobs; before rollout, the operator must verify the live server and off-host backup, snapshot and log retention settings.

What we process

To provide collaboration, we store account display names, device names and credential digests, project memberships, shared conversation and Agent output, optional cloud Git checkpoints, and necessary security and operational logs. Device access tokens are not stored in plaintext on the server. Signing in does not automatically upload local Codex / DeepSeek Harness files, native conversations or model credentials; connectors and plugins upload selected content only for features you enable.

Optional email registration and password sign-in (not deployed)

The official Alpha has not opened email registration. If explicitly enabled, email identifies a sign-in account and receives a short-lived code; passwords enable later sign-in. We retain keyed email digests, short-lived code digests and salted password hashes, not plaintext email, codes or passwords. Digests are pseudonymous personal data. Email accounts have the same project permissions as qualification accounts; project members cannot read these credential records. Existing accounts are never automatically bound or combined.

Cloudflare Turnstile loads only after acknowledgment and processes browser/network information under its Privacy Addendum. The configured mail provider handles recipient addresses, code content and delivery status. The current adapter uses Resend under its privacy policy and retention settings. Before opening, operators must verify providers, cross-border processing and actual retention, and disclose any change. Codes, passwords and tokens do not enter URLs, ordinary logs or browser local storage.

Pending records are removed within one minute of expiry while the host runs (codes last ten minutes). Budget digests expire with their windows, at most 31 days. Active email identifiers/password hashes last until account deletion; deletion removes them from the live service while retaining a mailbox digest for 30 days to prevent immediate signup-budget evasion. A 30-day HttpOnly browser marker binds password sign-ins to independent devices and cannot authenticate by itself. Backups follow the 14-day policy below; provider and recipient mailbox copies follow their own policies. Password recovery, email changes and converting legacy qualification accounts are not available yet.

What project members can see

Project members can read that project's shared conversation history and uploaded cloud code. Solo restricts others' writing; it is not private storage. Do not upload secrets you do not want project members to see. A user's name or other identifying information written into shared Multi content or code is not automatically rewritten when that account is deleted.

Optional GitHub file synchronization

If you choose GitHub file synchronization, an authorized local connector uploads code directly to your selected GitHub repository, not through GatherThread servers. GatherThread stores repository and branch configuration and operation status, not GitHub credentials. GitHub visibility, collaborator access and retention are independent of GatherThread; a public repository may be read by anyone. Project and account digests in personal branch names are stable pseudonymous identifiers, not a guarantee of anonymity. Pausing synchronization, leaving a GatherThread project or deleting a GatherThread account does not revoke GitHub access or delete GitHub branches or history. Manage those separately on GitHub. The 14-day GatherThread backup and Git-object limits below do not apply to GitHub, its Actions artifacts or other people's clones.

Delete your account

Use “Settings → Account & privacy” in the workspace. First transfer every project you own to an existing participant or delete it, and resolve personal cloud code branches. The page previews how many Solo cloud conversations will be deleted. After confirmation, Solo cloud conversations are deleted, device credentials, sessions and membership links are revoked, and shared Multi records remain with their server-side author account association changed to “Deleted member”. GatherThread does not remotely delete local Agent conversations, workspaces or files.

Retention after deletion

The live service stops serving deleted Solo conversations and account data immediately after the deletion transaction. Routine backups containing deleted material, and cloud Git objects that become unreachable after deletion, are retained for no more than 14 days; routine operational and security logs containing user identifiers are retained for no more than 30 days. The clock starts when the relevant data is deleted or the log is created. Backups are used only for disaster recovery, not ordinary conversation access; restoring an older backup must reapply subsequent account and content deletions before serving users.

Shared Multi content and Git objects still reachable from a project's main line or another member's branch are not “unreachable after deletion” and remain with the project. Git commit metadata may retain the original author's display name; account deletion does not rewrite shared Git history. User exports, other members' local copies and data held by third-party Agents or model providers are outside the GatherThread server's deletion control. If evidence must be preserved by law, an individual restricted copy may need a longer retention period, with its scope separately recorded and disclosed.
