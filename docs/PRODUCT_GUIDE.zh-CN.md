# 一起做个报名页：GatherThread 图文指南

**一起讨论，调用自己的 AI Agent，检查文件成果，换个设备接着做。** 这里用一个社团报名页，带你走完这条协作流程。

[开始使用](https://gatherthread.cn/app/) · [打开自由示例](https://gatherthread.cn/app/example.html?locale=zh-CN&topic=browse) · [返回介绍](../README.zh-CN.md) · [English](PRODUCT_GUIDE.md)

图片为真实应用隔离自由示例的完整界面，并配以重点标注；人物、讨论和 Agent 回答为演示内容。示例不运行真实模型，不改变你的项目。

## 先认识一起工作的地方

左边选项目与会话，中间讨论和请求 AI，右边看成员、邀请同伴。两个侧栏可收起，给工作留更大的地方。

![完整界面与重点标注：项目、会话、成员与 AI 操作](assets/product/zh-CN/annotated/01-workspace.jpg)

真实使用时，验证邮箱并设置密码，登录后创建项目和一个 Multi 多人会话，再邀请同伴。已有邀请？登录后在成员侧栏输入邀请密钥即可加入。

可以直接选择云端体验 Agent 做小任务；也可以在电脑上用[启动器连接 Codex](CODEX_CONNECT.zh-CN.md)，或[配对 DSH 插件](DSH_CONNECT.zh-CN.md)。启用哪些 Agent 在设置里选，手机无需安装本地 Agent。

## 1. 先把目标说清楚

林悦想做报名页，陈晓确认时间、地点和按钮效果。两个人看的是同一段讨论，不必反复转发给 AI。普通聊天不会启动 Agent。

![完整界面与重点标注：确认报名页的功能范围](assets/product/zh-CN/annotated/02-discussion.jpg)

可尝试发送：“先做一个报名页，只要时间、地点和报名按钮，照片以后再加。”

## 2. 对着具体消息讨论

每条历史消息旁的引用按钮可以引用聊天、Agent 回复或摘要，发送前在输入框上方核对引用。输入 **@** 后从成员列表选人，对方可从顶部 **@** 入口快速定位消息。

![完整界面与重点标注：引用预览与已选择的提及对象](assets/product/zh-CN/annotated/05-quote-and-mention.jpg)

![完整界面与重点标注：从提及入口定位消息](assets/product/zh-CN/annotated/06-mentions.jpg)

引用与 @ 是沟通方式，不会自动调用被提及成员的 Agent。

## 3. 讨论多了，整理成制作清单

选好自己已连接的电脑 Agent（Codex/DSH）后，点击“选择历史生成摘要”，选中需要整理的消息，再确认生成。这里把活动要求整理成清单，并说明这次不做照片。摘要是可选步骤，也会使用所选 Agent 的额度。

![完整界面与重点标注：制作清单与原文切换](assets/product/zh-CN/annotated/03-summary.jpg)

摘要旁的箭头只切换本段原文/摘要；顶部箭头切换全部。旧摘要与原文仍保留，版本入口可查看来源；有发言权限的成员可用自己的 Agent 重新生成，也可把已有摘要和其他消息一起选中，再整理一遍。

**后续网页任务默认参考摘要整理后的历史。** 在“设置 → 摘要”可改用原文，也可修改总结要求。摘要更集中，但可能漏细节；原文更完整，但占用更多模型注意力。阅读时切换原文，不会自动改变这个设置。

![完整界面与重点标注：摘要设置与总结要求](assets/product/zh-CN/annotated/10-summary-settings.jpg)

## 4. 请自己的 Agent 做，大家看进展

陈晓在消息框写下明确任务，点击 **请求我的 Agent**。回答标明归属、Agent 和模型，公开工作进展可展开；队友在同一会话中跟进，不必再向他索要结果。

![完整界面与重点标注：Agent 制作结果与检查说明](assets/product/zh-CN/annotated/04-agent-work.jpg)

可尝试请求：“按上面的清单制作报名页，只做已经确定的功能。完成后告诉我们做了什么、检查了什么。”

模型和思考强度以所选 Agent 实际支持的选项为准。电脑上直接选择，手机和平板通过紧凑的 Agent 按钮展开。电脑 Agent 请求处理中，原请求按钮可暂停或继续；继续会重新发起工作，不是冻结并恢复原生 Agent 全部内部推理状态。每个人只请求自己账号下的 Agent。

## 5. 给项目文件选个家

点击顶部的“项目文件协作”图标，选择 **GitHub** 或 **GT Cloud**。这与会话历史同步是两件事；上传代码文件需要单独授权，先检查目录、文件与敏感信息。

**实际开发、长期项目优先 GitHub。** 每个人授权自己的连接，文件直达个人 GitHub 分支，不占 GatherThread 文件额度。项目成员身份不等于 GitHub 仓库权限；请按仓库自己的规则授权协作者。

![完整界面与重点标注：GitHub 连接与个人分支同步](assets/product/zh-CN/annotated/09-github.jpg)

**小项目和轻量体验可用 GT Cloud。** 每用户有 128 MiB 有效云端文件版本额度，无需先配置 GitHub，也能在工作页看版本、审查差异并发起恢复。

![完整界面与重点标注：项目文件服务选择](assets/product/zh-CN/annotated/07-file-service.jpg)

两种服务分别管理，选择一种不会搬迁另一种的文件。GitHub 仍受自身规则与本地传输安全限制；这里保存符合规则的项目代码文件，不是任意文件网盘或完整电脑备份。

## 6. 各自提交，检查后整合

陈晓先做页面，林悦改善成功提示。每个人先把改动保存到自己的分支，再查看别人的版本与改动。在这个 GT Cloud 示例中，林悦提交审核，项目创建者明确确认后才合并到共享版本。

![完整界面与重点标注：个人分支与提交审核状态](assets/product/zh-CN/annotated/07-file-versions.jpg)

![完整界面与重点标注：报名提示的文件差异与审核](assets/product/zh-CN/annotated/08-review-changes.jpg)

使用 GitHub 时，通过仓库的 PR 流程审核，合并权限按 GitHub 设置。**自动上传不是自动合并**，也不是自动覆盖本地文件：同步等待任务空闲和文件稳定；下载与整合由你确认。个人分支不隔离本地目录，多人或多个 Agent 同时改文件时，请使用不同的工作目录。

换电脑或文件丢失？从在线且已授权的电脑设备下载更新，或恢复已上传版本到新目录。旧目录不被覆盖，未上传的改动无法恢复。会话自动上传与文件自动上传是不同开关；GT Cloud 文件自动上传默认关闭，GitHub 授权同步的自动上传可在各自设置中关闭。

[完整的文件同步、恢复、额度与限制 →](CODE_SYNC.md)

## 7. 看看成果能不能用

自由示例包含可点击的报名页。按一下“我要报名”，看看是否出现约定的成功提示。对照讨论检查成果，比只看到“完成了”更可靠。

![完整界面与重点标注：报名页的成功提示](assets/product/zh-CN/annotated/14-working-result.jpg)

这张图是示例内已有页面的实际运行结果，不代表模型在本轮重新制作了它。

## 8. 换个设备，继续推进

电脑、手机、平板可同时登录同一账号。手机上继续讨论、查看进度，或调用自己在电脑上连接好的 Agent；不必与电脑同一网络，也不必靠近电脑，只需能访问所用服务器。**使用电脑 Agent 时，电脑和连接器必须保持在线。** 也可直接使用云端体验 Agent。

<img src="assets/product/zh-CN/annotated/12-phone.jpg" alt="完整界面与重点标注：手机继续共享会话" width="390">

点击输入区的 Agent 按钮，就能展开设备、模型与思考强度；手机不显示本地连接步骤。项目、成员和设置收进菜单，新手引导也按移动端的位置说明。

<img src="assets/product/zh-CN/annotated/12-phone-agent.jpg" alt="完整界面与重点标注：手机 Agent、模型与思考强度" width="390">

平板沿用同一风格，让讨论保持主角。另一台电脑要接着改文件，先下载所选服务中已保存的版本，检查后再继续。

<img src="assets/product/zh-CN/annotated/13-tablet.jpg" alt="完整界面与重点标注：平板会话与操作入口" width="640">

## 本地会话与共享历史，各自控制

共享讨论会传给已连接的 Agent；在 Codex 或 DSH 内完成的本地回合，也可自动或手动上传到云端。工作页的“会话状态详情”内可关闭 **本地回合自动上传至云端**，或使用 **立即从本地上传至云端** 补传已完成回合；手动上传不会重新开启自动上传。DSH 的插件界面也提供相应操作。

![完整界面与重点标注：会话状态中的本地上传控制](assets/product/zh-CN/annotated/15-history-controls.jpg)

Codex 还可以在初次建立连接时导入可见历史，也可手动“导入 Codex 历史”。**手动导入建立新的本地任务，不覆盖旧任务；旧任务由你自行归档。** 旧任务继续工作只留在本地，实时共享历史传递不受影响。摘要设置也不会倒改已有原生对话。

长历史由 Agent 自身的能力与压缩设置处理，不是无限记忆；遇到模型上限时，请整理摘要、选择合适模型或按接入指南处理，不要删掉共享原文来绕过问题。

[Codex 同步与导入](CODEX_CONNECT.zh-CN.md) · [DSH 同步与本地操作](DSH_CONNECT.zh-CN.md)

## 共享范围和账号，心里有数

- **Multi 多人会话**：创建者与参与者能发言、请求自己的 Agent；访者只读，不能生成摘要。
- **Solo 个人会话**：只有创建者操作，项目成员仍能阅读。它不是私聊；个人文件分支也不保证私密。
- **邀请与退出**：项目创建者可邀请、调整角色和移除成员；参与者与访者可退出他人项目。离开 GT 项目不会自动撤销独立 GitHub 仓库权限。
- **多设备**：退出当前浏览器不影响其他设备；设置中可查看并单独撤销设备。重置密码会撤销全部会话及 Agent 授权。
- **注销账号**：先移交自己创建的项目。确认影响后删除个人 Solo，共享 Multi 内容保留但解除账号与设备关联；不会删除本地文件。

聊天与授权上传的本地回合进入 GatherThread；文件进入所选服务；云端 Agent 会把任务及所选内容交给对应模型服务。不要输入秘密，上传前检查范围。本地 Agent 的模型凭据和工具批准权不因共享会话交给同伴。

[隐私与删除保留说明](https://gatherthread.cn/privacy/) · [安全反馈](../SECURITY.md)

## 开始自己的项目

打开[自由示例](https://gatherthread.cn/app/example.html?locale=zh-CN&topic=browse)先试一遍，随时重置；再回到自己的项目。设置中的新手引导、摘要、Agent 与上传开关可按需调整。界面支持中文/英文，语言会在首页、登录页与工作页之间同步。

现在是多人共享讨论、各自调用 Agent、共同审查和整合。未来我们会继续探索个人多 Agent 自动分工、不同成员的 Agent 直接合作、多个云端 Agent 组队；这些自动团队能力仍是规划。
