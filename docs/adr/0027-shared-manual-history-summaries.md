# ADR-0027: Shared manual history summaries and derived Agent context

- Status: proposed / source preview, pending cross-harness and release review
- Date: 2026-09-23
- Builds on: [ADR-0026](0026-native-first-context-management.md)

## Context

Long shared sessions are hard to scan and can distract a local Agent even when the native harness automatically compacts its own context. Native compaction is private and cannot serve as an attributed, switchable summary for every project member. GatherThread must let a writer choose specific public messages, ask their own registered local Agent to summarize them, and retain the exact original conversation for checking or later re-selection.

## Decision

1. A session writer explicitly selects 1–100 public completed conversational messages. The server freezes their exact canonical IDs and text, bounds the complete UTF-8 selection and prompt, and creates an ordinary `agent_request` targeting the initiating user's exact online execution runtime and selected model. The normal claim lease, attempt fencing, progress, completion, quota and failure rules apply. A viewer can read versions and originals but cannot initiate generation. No other member's runtime is borrowed.
2. The request carries server-created `history_summary` metadata: version, ordered source event IDs and SHA-256 of the validated source serialization. The completed `agent_response` is the derived version. Its canonical reply relationship, actor and successful status are required to activate it; payload claims are insufficient. Each new generation is a new version. Older versions and their source events remain unchanged, including overlapping selections.
3. Every member can read all public versions and switch the Web timeline between compact and original display. Summary cards label their author and sources and are explicitly lossy. An original may be selected again even if a newer summary currently covers it. A completed summary's **own text** can also be selected alongside other sources for another summary. Selection mode and settings are accessible and bilingual. A user can edit or reset their own summary instructions; the server's safe default asks for confirmed facts, decisions, constraints, disagreements, uncertainty, source references and next steps. Selected history is untrusted JSON data, not operational instructions.
4. The per-user, per-project `context-policy` chooses `summary` (default) or `original`; changing it never rewrites canonical events or another member's setting. The authenticated derived context read returns only public conversational text. For `summary`, the newest successful non-overlapping whole versions replace their exact source IDs once; references to an earlier summary expand to that summary's original source ancestry before overlap resolution. This prevents both a nested summary and its ancestor from entering the same context. An older overlapping version remains viewable, but its noncovered originals reappear so the projection loses nothing silently. `original` returns the source messages. A frozen `through_sequence` binds an Agent request to the history it could have observed. Oversized derived reads fail explicitly; they do not silently clip messages.
5. The existing paginated canonical history API and realtime sequence remain exact and unchanged. The new context API and user MCP `collaboration_read_context` are read models, not replay cursors. Consumers must not treat a summary as provider-request fidelity or as proof that native automatic compaction occurred.
6. For a Web-triggered Codex Agent turn, the private connector-owned execution projection uses the selected context. If a summary version or context mode changes, it replaces only its hidden background task after its existing single-writer and unfinished-turn checks, then verifies fresh injection before running the turn. The visible Desktop task, its original bubbles, and local files are not replaced. Summary-generation control requests are omitted from passive Desktop projection and visible snapshot imports so their selected JSON does not appear twice; the resulting summary remains visible. A summary-generation turn starts in a separate clean hidden context containing its selected prompt, so unrelated previously loaded history is not included by GatherThread. Desktop's own active context still follows Codex native compaction rules.
7. DSH Web-triggered turns that need a summary-aware view use a GatherThread-owned execution Session with the same workspace path and validated native tool preset, separate from the ordinary native conversation. Its public native surface is replaced only while idle with the frozen derived read for that request; the underlying DSH event log remains recoverable. Summary generation uses an empty shared-history surface plus its selected-record prompt. Ordinary conversations with no summaries keep the existing native execution path. The original DSH conversation and local user turns are not rewritten. Passive remote assistant replies are carried as explicitly labelled plugin-source quotations, not synthetic local model turns: the pinned AgentLoop caches its turn number, and a synthetic remote turn would collide with the next native turn. Canonical actor/type remain unchanged. Unsupported ownership, busy parent or surface behavior fails visibly. Changing the context policy affects subsequent GatherThread Web Agent requests, not the already loaded native DSH task.

## Security, compatibility and limits

- The dedicated creation route validates current device, project membership, session write permission, exact runtime and immutable creator rules at the mutation boundary. Generic event/local-turn routes cannot spoof the reserved summary marker or the reply relationship. Completion remains bound to the initiating actor's exact runtime and claim attempt.
- Summary prompts contain only public allowlisted text/actor/sequence fields, never arbitrary payload objects or private event metadata. Source text is untrusted user/Agent content and can itself mention paths or secrets; the server applies its usual redaction, but a writer must review a selection before sharing its summary. A model might still ignore summarization instructions or produce an inaccurate result; original text and attribution remain available.
- Project role changes, deletion and revocation continue to govern summary reads and generation. Per-user context policy is data, not a grant to run an Agent, change upload consent, start native compaction or delete native tasks.
- The 20 KiB source limit, 30 KiB complete prompt limit, 100-source limit and 256 KiB derived context result limit are independent of native model context windows. They bound transport and server work; they are not a fake model-size cap.
- Existing event, local-turn, snapshot, Git, WebSocket and native upload protocols retain their wire behavior. New routes, metadata, UI controls and MCP tool are additive Alpha interfaces.

## Verification

Protocol tests cover disjoint and overlapping versions, exact source replacement, original recovery, failures and forged reply metadata. API tests cover writer/viewer/Solo/device/runtime authorization, changed retry payloads, byte limits and redaction. Browser tests cover selection, a generated version, original switch, re-selection, bilingual labels and settings. Connector tests must inspect actual native input for absence of shadowed originals, restoration on switching mode, and no mutation of an active visible Codex task or unrelated DSH messages. Real-model summary quality and provider quota are manual acceptance checks, not implied by mock tests.
