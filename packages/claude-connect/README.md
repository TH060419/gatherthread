# GatherThread for Claude Code

Use the GatherThread Launcher to connect Claude Code to a project. Sign in on the website, choose **Connect Claude Code**, select the exact model you use, then enter your account password only in the Launcher. Claude Code must already be installed and signed in. The connector does not install or pay for Claude.

For repository development, run `npm run claude:connect -- --url https://gatherthread.cn --project PROJECT_ID --workspace /absolute/project --model EXACT_MODEL_ID`. For an advanced standalone installation, use the matching reviewed local package:

```sh
npx --yes --package /absolute/path/to/LOCAL_CLAUDE_CONNECTOR.tgz gatherthread-claude-connect --url https://gatherthread.cn --project PROJECT_ID --workspace /absolute/project --model EXACT_MODEL_ID
```

The hidden terminal prompt accepts a one-use device authorization created by the signed-in website, never an account password. Launcher-provided device credentials remain private to the connector and are stripped from Claude children. No credential belongs in a command, repository, plugin manifest or model prompt.

The separate Claude Code plugin offers the GatherThread skill and focused project, history, chat, request, status and synchronization commands. Its MCP tools use only the exact local workspace's Claude connector. The npm package includes a complete matching plugin: `gatherthread-claude-connect plugin-path` prints its marketplace directory. Alternatively prepare matching source with `node plugins/gatherthread-claude/scripts/prepare-source-plugin.mjs`; add the printed marketplace directory through Claude's plugin interface and install `gatherthread@gatherthread-claude`. npm, source and Launcher marketplaces are alternative installation choices, not simultaneous requirements.

Add `--plugin-hooks` only after installing and reviewing the plugin's hooks. Direct native turns are bound to a personal Solo, with automatic upload initially off; approve per-conversation upload explicitly or manually upload completed captured turns. Stop records only the exact session's file-size watermark until that approval. Upload consent permits reading at most 1.25 MiB around the captured turn in its trusted local transcript to verify the actual model and prompt/answer identity, not arbitrary transcript discovery or unrelated history. The plugin does not capture hidden thinking. Ordinary offline/connection errors do not block local Claude use.

Web requests run in separate connector-owned Claude processes; shared server history remains authoritative. Calling your own Agent keeps its native tools, local configuration, sandbox and permission rules, including terminal commands, dependency installation, subagents and configured MCP tools when locally permitted. There is no extra file/plan-only execution whitelist. Public answers, selected tool activity and plans stream without raw command/MCP arguments or tool-result bodies. Code synchronization requires separate `--code-sync` or `--github-code-sync OWNER/REPO` authorization, reviewed hooks and an idle workspace. While this connector is synchronizing local files or running a remote Claude request, its trusted Hook asks an unrelated new native prompt to wait; Hooks from the exact owned Web execution do not recapture or block it. This coordination covers the current connector and installed Hooks, not unrelated programs or an operating-system-wide file lock.

`--preflight-only` checks local CLI compatibility and login plus server/project access without calling a model. `--permission-mode native` is the default and does not override Claude's configured mode; explicit `manual` and `plan` overrides remain available. Native settings, deny rules and sandbox remain authoritative. New interactive permission prompts cannot be approved through this unattended path: authorize the required operation locally and create a new request. The connector never adds permission-bypass flags. Use `--help` for current options. Stop the Launcher/connector to disconnect; cloud deletion never deletes local files or native conversations. Other members' isolated shared-Agent execution is separate; Claude sharing is not offered.
